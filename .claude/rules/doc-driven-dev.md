# 문서 기반 개발 규칙 (Document-Driven Development)

> **핵심 원칙: 문서가 개발의 중심이다. 코드는 문서를 구현한 것이다.**
>
> 모든 개발은 문서에서 시작하고, 문서로 진행을 추적하며, 문서로 검증한다.
> 문서 없는 개발은 방향 없는 항해와 같다.

---

## 1. 제1원칙: 문서가 곧 방향이다

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                  │
│   ❌ 코드 먼저 → 나중에 문서화                                    │
│   ✅ 문서 먼저 → 문서를 보며 개발 → 문서로 검증                   │
│                                                                  │
│   문서는 "기록"이 아니라 "나침반"이다.                             │
│   개발 중 방향이 흔들리면 문서를 다시 읽는다.                      │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

### Claude 자동 실행 규칙

| 시점 | Claude가 하는 일 | 확인 |
|------|------------------|------|
| **세션 시작** | PRD/진행 문서 읽기 → 현재 위치 파악 | "지금 어디까지 했지?" |
| **개발 중 (매 마일스톤)** | 진행 문서(DEV_) 업데이트 | "문서 방향과 일치하나?" |
| **기능 완료** | PRD 체크리스트 확인 | "PRD 요구사항 충족했나?" |
| **세션 종료** | 진행 문서 최종 업데이트 + MarkdownBlog 동기화 | "다음 세션에서 이어갈 수 있나?" |

## 2. 문서 체계

### 2.1 개발 사이클별 문서

```
1. PRD (기획)         → docs/plan/PRD_xxx.md       → "뭘 만들 것인가"
2. TECHSPEC (설계)    → docs/plan/TECHSPEC_xxx.md   → "어떻게 만들 것인가"
3. DEV (진행/완료)    → docs/DEV_xxx.md             → "어떻게 만들고 있는가 / 만들었는가"
4. QA (검증)          → docs/QA_xxx.md              → "제대로 만들었는가"
```

### 2.2 문서 흐름

```
PRD 작성
  ↓
"go" → PRD 확인 → 진행 문서(DEV_) 생성
  ↓
개발 중 → DEV 문서 실시간 업데이트
  ↓  ← 방향 체크: "PRD 요구사항과 일치하는가?"
  ↓
마일스톤 완료 → DEV 문서 업데이트 + PRD 체크
  ↓
전체 완료 → DEV 문서 완료 처리
  ↓
"테스트해줘" → QA 문서(QA_) 생성 + 검증
  ↓
문서 공유 → MarkdownBlog 동기화
```

### 2.3 기록 위치

| 기록 | 위치 | 동기화 |
|------|------|:------:|
| **PRD** | `docs/plan/PRD_xxx.md` | MarkdownBlog + Git |
| **TECHSPEC** | `docs/plan/TECHSPEC_xxx.md` | MarkdownBlog + Git |
| **진행/완료** | `docs/DEV_xxx.md` | MarkdownBlog + Git |
| **QA 결과** | `docs/QA_xxx.md` | MarkdownBlog + Git |
| **참조** | `docs/REF_xxx.md` | MarkdownBlog + Git |

> **Dev Hub(community.ilouli.com) → MarkdownBlog(markdown.ilouli.com)로 기록 이관**
> MarkdownBlog가 모든 개발 문서의 단일 저장소(Single Source of Truth)가 된다.

## 3. "go" 명령어 (강화)

`go`라고 말하면 다음 순서로 실행한다:

### Step 1: 현재 위치 파악

```
1. 현재 프로젝트의 docs/plan/PRD_*.md 확인
2. docs/DEV_*.md 진행 문서 확인
3. 미완료 마일스톤/작업 확인
```

### Step 2: 진행 문서 생성 또는 업데이트

PRD가 있으면:
- `docs/DEV_{기능명}.md` 생성 (없으면) 또는 업데이트 (있으면)
- 진행상황 섹션에 현재 시간 + 작업 목표 기록

PRD가 없으면:
- "PRD를 먼저 작성할까요?" 확인

### Step 3: 개발 시작

```
📍 현재 위치: {PRD 마일스톤 N} / {작업 항목}
📄 기준 문서: docs/plan/PRD_xxx.md
📝 진행 문서: docs/DEV_xxx.md

개발을 시작합니다.
```

### Step 4: 방향 체크 (개발 중 자동)

**매 주요 작업 완료 시** Claude는 자동으로:
1. PRD 요구사항과 현재 구현을 비교
2. 벗어난 부분이 있으면 사용자에게 알림
3. 진행 문서 업데이트

```
⚠️ 방향 체크: PRD §3.2에서 "카테고리 필터는 URL에 반영"을 요구하지만,
현재 구현은 내부 state만 사용합니다. URL 반영을 추가할까요?
```

### Step 5: 세션 종료 시

```
1. DEV 문서에 진행상황 최종 업데이트
2. MarkdownBlog 동기화
3. 다음 작업 항목 명시
```

## 4. 진행 문서(DEV_) 형식

### 개발 중 (in-progress)

```markdown
# {기능명} 개발 기록

> **PRD**: docs/plan/PRD_xxx.md
> **시작일**: YYYY-MM-DD
> **상태**: 🔄 진행 중
> **현재 마일스톤**: M2 - {마일스톤명}

---

## 진행상황

### YYYY-MM-DD (최신이 위)
- [HH:MM] {완료한 작업}
- [HH:MM] {완료한 작업}
- [HH:MM] 작업 시작

### YYYY-MM-DD (이전)
- [HH:MM] ...

---

## PRD 체크리스트

- [x] M1: {마일스톤 1} ✅ YYYY-MM-DD
- [ ] M2: {마일스톤 2} ← 현재
- [ ] M3: {마일스톤 3}

---

## 변경 파일

| 파일 | 변경 | 커밋 |
|------|------|------|
| {파일} | {변경내용} | {hash} |

---

## 다음 작업

- [ ] {할 일 1}
- [ ] {할 일 2}
```

### 개발 완료 (completed)

```markdown
> **상태**: ✅ 완료
> **완료일**: YYYY-MM-DD

## PRD 체크리스트
- [x] 전체 완료

## QA
- 📄 docs/QA_xxx.md (점검 완료)
```

## 5. MarkdownBlog 동기화

### 🚨 핵심 규칙: 문서 생성 = 즉시 동기화 + 링크 제공

> **모든 문서 생성/수정 후 반드시: Git 커밋+푸시 → MarkdownBlog 동기화 → 링크 제공**
> **사용자가 "문서 올려줘"를 별도로 말할 필요 없이 자동으로 완료한다.**

```
문서 생성/수정 완료
  ↓ (자동)
git add + commit + push
  ↓ (자동)
MarkdownBlog sync API 호출 → docId 확보
  ↓ (자동)
📄 문서 동기화 완료
- GitHub: https://github.com/feelgame3025/{repo}/blob/main/{path}
- MarkdownBlog: https://markdown.ilouli.com/project/{project}/{docId}
```

**이 규칙이 적용되는 스킬:**
- `doc-prd` (계획문서 작성해줘)
- `doc-techspec` (테크스펙 만들어줘)
- `dev-complete` (개발완료)
- `qa-test` (테스트해줘)
- 기타 `docs/` 폴더에 문서를 생성하는 모든 작업

### 자동 동기화 (post-commit hook)

`docs/` 폴더의 접두어 문서가 커밋되면 자동으로 MarkdownBlog에 동기화:
- `PRD_`, `TECHSPEC_`, `DEV_`, `QA_`, `REF_`, `GUIDE_` 등

### 수동 동기화

"문서 올려줘" 또는 `doc-view` 스킬 실행 시:

```bash
# MarkdownBlog sync API
POST http://localhost:4009/api/projects/sync
{
  "project": "{프로젝트명}",
  "file_path": "docs/DEV_xxx.md",
  "content": "{문서 내용}",
  "git_hash": "{커밋 해시}",
  "device": "{기기명}"
}
```

### 문서 열람

| 위치 | URL |
|------|-----|
| **MarkdownBlog** | `https://markdown.ilouli.com/project/{프로젝트명}/{docId}` |
| **GitHub** | `https://github.com/feelgame3025/{repo}/blob/main/docs/{파일명}` |

## 6. 방향성 체크 규칙

### 언제 체크하는가

| 시점 | 체크 내용 |
|------|----------|
| 새 파일 생성 시 | "이 파일이 PRD에 정의된 범위 내인가?" |
| API 엔드포인트 추가 시 | "TECHSPEC에 정의된 구조와 일치하는가?" |
| UI 컴포넌트 수정 시 | "디자인 문서(REF_)와 일치하는가?" |
| 마일스톤 완료 시 | "PRD 요구사항을 충족했는가?" |
| 세션 종료 시 | "다음 작업이 PRD 순서와 맞는가?" |

### 방향 이탈 시

```
1. 사용자에게 알림
2. PRD 수정이 필요하면 → PRD 업데이트 제안
3. 구현 수정이 필요하면 → 수정 후 진행
4. 의도적 변경이면 → 문서에 기록 ("PRD 변경: §3.2 수정 — {이유}")
```

## 7. 전체 워크플로우 요약

```
┌─ 기획 ─────────────────────────────────────────────┐
│ "PRD 만들어줘" → doc-prd → PRD 문서 생성           │
│ (필요시) "테크스펙" → doc-techspec → TECHSPEC 생성   │
│ → MarkdownBlog 동기화                               │
└─────────────────────────────────────────────────────┘
        ↓
┌─ 개발 ─────────────────────────────────────────────┐
│ "go" → PRD 확인 → DEV 문서 생성 → 개발 시작        │
│   ↓                                                 │
│ 개발 중 → DEV 문서 실시간 업데이트                   │
│   ↓  ← 방향 체크 (PRD 대비)                        │
│   ↓                                                 │
│ 마일스톤 완료 → PRD 체크 + DEV 업데이트             │
│   ↓                                                 │
│ 세션 종료 → DEV 문서 최종 업데이트                   │
│ → MarkdownBlog 동기화                               │
└─────────────────────────────────────────────────────┘
        ↓
┌─ 배포 ─────────────────────────────────────────────┐
│ "배포해줘" → dev-deploy → git push                  │
│ → GitHub Actions 빌드/배포                          │
└─────────────────────────────────────────────────────┘
        ↓
┌─ 검증 ─────────────────────────────────────────────┐
│ "테스트해줘" → qa-test → QA 문서 생성              │
│ → 이슈 발견 → 수정 → 재검증                        │
│ → QA 문서 최종 업데이트                             │
│ → MarkdownBlog 동기화                               │
└─────────────────────────────────────────────────────┘
        ↓
┌─ 완료 ─────────────────────────────────────────────┐
│ "개발완료" → dev-complete → DEV 문서 완료 처리      │
│ "문서 올려줘" → doc-view → 링크 공유                │
│ → MarkdownBlog에서 전체 기록 열람 가능              │
└─────────────────────────────────────────────────────┘
```

| 용도 | URL |
|------|-----|
| 프로젝트 전체 문서 | `https://markdown.ilouli.com/project/{프로젝트명}` |
